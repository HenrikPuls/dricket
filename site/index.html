Tickets that live in Git. Claimed by fast-forward. Safe for humans and agents.

dricket is a ticketing system with no server. Each ticket is a Markdown file. When two runners reach for the same ticket, Git decides who gets it, and the other one is told immediately.

How it works

The fast-forward is the lock.

1 · refresh

Runner A reads an immutable snapshot of the ticket branch.

2 · commit

A writes its claim on top: owner, lease, a new epoch.

3 · publish

Git accepts exactly one fast-forward, by remote push or local ref CAS.

4 · retry

B's publication is rejected. B refreshes, sees A owns the ticket, and moves on.

No server to run

Your Git host is the database and the lock manager. Nothing else to deploy, patch or monitor.

Markdown you can edit

One folder per ticket, comments as separate files, history in git log. Open it in any editor.

Stable paths and IDs

IDs like app-6842 are easy to say aloud. A ticket's path never changes when its stage does.

One tool in between

People and agents change state through a strict CLI, dk, so the files stay consistent.

Guardrails for collaboration

Built for runners that crash, stall and lose a claim.

Sstarts at 2 h
Mstarts at 8 h
Lstarts at 24 h, the default

Configurable starting values. The local concurrency spike checks correctness, not real-host performance.

Leases by size

A claim carries a size instead of a guessed duration. Extending needs a reason.

Cooperative fencing

Every claim or takeover raises an epoch. A compliant writer holding an old epoch is refused and told to stop.

Trusted collaborators

Repository writers collaborate. Agents normally stop at review; a human closes the ticket as a team convention.

Structural validation

Identity stays immutable. Revisions, epochs, ownership and lease fields must form a legal transition.

Safe publication

Whole-ticket commits require the exact edit base. Dirty work and unpushed local commits are preserved.

Comments during a claim

Separate add-only comments do not change the ticket version. Inbox reports them between work steps.

A session

Edit the file. Publish with confidence.

$ dk claim app-1 --size M
claimed app-1 (epoch 1, lease until …)
$ dk sync
synced tickets
$ $EDITOR tickets/app/0000/app-1/ticket.md
$ dk inbox app-1
comment … henrik: please check the empty-password case
$ dk commit app-1
committed app-1 (rev 2, commit …)
$ dk release app-1 --stage review --result "Fix on dk/app-1"
released app-1 -> review

Verified development-branch workflow; timestamps and commit IDs shortened.

Trust and integrity

Collaborators write. The protocol keeps state coherent.

dricket checksGit host ownsNot promised
Document shape, immutable identity, legal revision/epoch/claim transitions and safe local-work preservation. Authentication, credentials and branch rights. Repository writers are trusted collaborators. Proof of actor truthfulness, real timestamps or protection against external side effects by a stale agent.

Ticket text remains untrusted input. Comments are asynchronous review input, not an interrupt channel.
