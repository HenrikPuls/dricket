Tickets that live in Git. Claimed by push. Safe for humans and agents.

dricket is a ticketing system with no server. Each ticket is a Markdown file. When two runners reach for the same ticket, Git decides who gets it, and the other one is told immediately.

How it works

The push is the lock.

1 · fetch

Runner A reads the current state of the ticket branch.

2 · commit

A writes its claim on top: owner, lease, a new epoch.

3 · push

Git accepts exactly one push that is a fast-forward.

4 · retry

B's push is rejected. B fetches, sees A owns the ticket, and moves on.

No server to run

Your Git host is the database and the lock manager. Nothing else to deploy, patch or monitor.

Markdown you can edit

One folder per ticket, comments as separate files, history in git log. Open it in any editor.

Stable paths and IDs

IDs like app-6842 are easy to say aloud. A ticket's path never changes when its stage does.

One tool in between

People and agents change state through a strict CLI, dk, so the files stay consistent.

Guardrails for agents

Built for runners that crash, stall and overreach.

Sstarts at 2 h
Mstarts at 8 h
Lstarts at 24 h, the default

Starting values from the design, not measured. They are configuration, and a spike will test them.

Leases by size

Language models estimate durations badly, so a claim carries a size instead of a guess. Extending needs a reason.

Fencing with an epoch

Every claim or takeover raises a counter. A writer holding an old epoch is refused, and told to stop.

Roles

Agents take a ticket up to review. A human closes it. The rules live in a protected config.

Strict validation

Identity fields cannot change. State changes only by command. Free fields are checked on every write.

Takeover after expiry

A dead claim does not block forever. After the lease plus a grace period, another runner can take over.

Separate accounts

Several agents on one machine can push as different Git accounts through profiles.

A session

Four commands, one ticket.

$ dk add -c "Login error on empty password" -l bug
app-6842
$ dk claim app-6842 --size M
claimed app-6842 (lease until 18:02, epoch 3)
$ dk update app-6842 --note "Root cause found"
$ dk release app-6842 --stage review --result "Fix on dk/app-6842"
released app-6842 -> review

Target behaviour, written from the design. It will be replaced with a recording of the real tool.

Security model

What it prevents, and what it only detects.

PreventedOnly detectedOut of scope
Accidental double work, stale writers, malformed tickets, forbidden transitions made through the tool. Edits made around the tool. dk validate finds them afterwards. An agent with shell access in the same operating-system user. Use separate users or containers and host-side branch rules.

Ticket text is untrusted input. Agents never follow instructions found in it.
